MUGA: Hover Preview Fixture #1028

Manual validation for src/content/hover-preview.js · Open with the extension active in Chrome

How to use this page: Hover your mouse over a test link below and hold it still for about 2.5 seconds — do not click. If MUGA's local unwrap changes the link's destination host, a small tooltip appears near the link showing "Goes to: <cleaned URL>". Moving the mouse, scrolling, or pressing Escape cancels the hold and hides the tooltip. This feature is desktop-only (fine pointer + hover capability) and fully local — no network requests are made to resolve any link.

Section 1 · Wrappers MUGA unwraps tooltip SHOULD appear

HP-01
Facebook outbound link (l.facebook.com/l.php)
Hover and hold ~2.5s without clicking.
https://l.facebook.com/l.php?u=https%3A%2F%2Fshop.example.com%2Fproduct%3Fid%3D9%26utm_source%3Dfb&h=AT1abc
Expected tooltip: Goes to: https://shop.example.com/product?id=9
Recipe: facebook-l — hostPatterns: l.facebook.com · pathPrefix: /l.php · extractor: fromParam "u" (src/rules/wrappers.data.js). Host changes l.facebook.com → shop.example.com, and utm_source is stripped by the normal cleaning pass that runs on the unwrapped URL.
HP-02
Reddit mail redirect (click.redditmail.com)
Hover and hold ~2.5s without clicking.
https://click.redditmail.com/redirect?url=https%3A%2F%2Fnews.example.org%2Fpost%3Fid%3D3
Expected tooltip: Goes to: https://news.example.org/post?id=3
Recipe: click-redditmail-com — hostPatterns: click.redditmail.com · no pathPrefix (any path matches) · extractor: fromParam "url" (src/rules/wrappers.data.js). Host changes click.redditmail.com → news.example.org.
HP-03
DuckDuckGo redirect (duckduckgo.com/l/)
Hover and hold ~2.5s without clicking.
https://duckduckgo.com/l/?uddg=https%3A%2F%2Fnews.example.org%2Fart%3Fid%3D5
Expected tooltip: Goes to: https://news.example.org/art?id=5
Recipe: duckduckgo-com — hostPatterns: duckduckgo.com, www.duckduckgo.com · pathPrefix: /l/ · extractor: fromParam "uddg" (src/rules/wrappers.data.js). Host changes duckduckgo.com → news.example.org.

Section 2 · Plain links tooltip should NOT appear

HP-04
Fully clean link, same host
Hover and hold ~2.5s. Nothing has to be cleaned, so there is no hidden destination worth surfacing.
https://example.com/clean-page
Expected: No tooltip (destination host unchanged)
HP-05
UTM-only tracking link, same host
MUGA strips the UTM params on click, but the destination host is still example.com either way — no wrapper is involved.
https://example.com/page?utm_source=x&utm_medium=y
Expected: No tooltip (destination host unchanged, even though params would be stripped on click)

Section 3 · Coverage tracker no known gaps today

This section tracks redirect networks that were known but not yet in MUGA's signed wrapper recipes. As recipes are added (hand-authored or via the unwrap-harvest pipeline), the corresponding entry flips from ⏳ to ✅ and moves into Section 1. There are no outstanding gaps right now: the remaining ClearURLs redirections MUGA does not unwrap are ad-click / affiliate-deeplink networks (e.g. googleadservices.com, adform.net), deliberately excluded because the click there IS the attribution event (ADR-0005) — not coverage gaps.
HP-06
Google search redirect (google.com/url) ✅ COVERED (#1028 follow-up)
Hover and hold ~2.5s without clicking.
https://www.google.com/url?q=https%3A%2F%2Fnews.example.org%2Fart%3Fid%3D5&sa=U
Expected tooltip: Goes to: https://news.example.org/art?id=5
Recipe: google-url — hostPatterns: ^(?:www\.)?google\.(?:[a-z]{2,3}|(?:co|com|org|net|ac|gov|edu)\.[a-z]{2})$ · pathPrefix: /url · extractor: fromAnyParam ["url","q"] (src/rules/wrappers.data.js). Host changes www.google.com → news.example.org, so the tooltip appears. The scoped host regex covers all Google ccTLDs while rejecting impostors like google.evil.com.

Section 4 · Gate checks (manual)

These are behavioural gates around the tooltip itself, not individual links. Verify each one by hand.
  • Settings → Advanced → disable "hover preview" → no tooltip appears on any HP-01/02/03 link
  • Re-enable "hover preview" in Settings → Advanced → tooltips return on HP-01/02/03
  • Pause MUGA for this site from the popup → no tooltip appears on any link on this page
  • Un-pause the site → tooltips return
  • Tooltips are PC-only: on a touch device (or Chrome DevTools device emulation with touch enabled), no tooltip ever appears, even after a long press
  • Clicking any link on this page (HP-01 through HP-06) still navigates normally — the hover preview never interferes with the click
  • The hold delay is roughly 2.5s: moving the mouse away before ~2.5s has elapsed cancels the tooltip; holding past ~2.5s shows it
