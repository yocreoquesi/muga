# Settings page fixes: #1473, #1479, #1480

## Objective

Fix three issues found by the pre-release multi-agent audit (2026-09-27)
of `main` at `ebda114`, all in the Settings page (`src/options/*`,
`src/lib/i18n.js` / `src/lib/locales/*`), before the 3.2.0 release.

## Scope

- #1473 (HIGH, unreleased regression from #1464): turning off "Record
  per-domain statistics" or "Cross-site identifier detection" hid the
  panel containing the switch itself (and Reset stats), making it
  unreachable from the UI.

  Advanced settings (dev-mode) was already on (off by default).

  entry only protects affiliates, when `isSiteFullyExempt` actually pauses
  all cleaning on that domain.

Out of scope: any other Settings issue, any behavior change to
`isSiteFullyExempt`/`processUrl` itself (#1480 is copy-only, per the
issue's own "the fix is copy-only and cheap" verifier note).

## Native review follow-up (advisory findings, addressed in commit 5)

Native review approved the branch but flagged 3 advisory findings, all
fixed in the same worktree/branch with new commits (no push):

1. `revealAggressivePrivacySection` no longer pokes
   `setDevMode()`/`syncDevTools()` directly. A new shared
   `handleDevModeChange()` is now the single path both the real
   `#dev-mode` checkbox's own "change" listener AND
   `revealAggressivePrivacySection()` go through: it awaits
   `setDevMode()`, and on rejection reverts the checkbox (and re-hides
   the card via `syncDevTools()`) so storage and the UI can never
   disagree. `revealAggressivePrivacySection` awaits it and only
   scrolls/focuses the section if the checkbox is still checked
   afterwards.
2. Focus now uses `section?.focus({ preventScroll: true })` after the
   smooth `scrollIntoView()`, so a bare `focus()`'s own instant
   scroll-into-view can't fight the animation just started.
3. `tests/e2e/options.spec.mjs`: seeded-state cleanup (blacklist,
   `referrerBeaconNoticeShown`, `devMode`, `domainStats`,
   `crossSiteFrequencyEnabled`, `stripAllAffiliates`) moved into
   `test.afterEach` hooks that write storage directly via
   `seedStorage`, so a thrown assertion mid-test can no longer skip a
   trailing manual reset line and leak state. The #1473 "re-enable"
   step now asserts the VISIBLE toggle (`label.toggle:has(#id)` — the
   label/slider a real user sees and clicks, not the opacity:0/0x0
   input) is visible, then clicks it for real via Playwright's own
   actionable `.click()`, instead of the `setCheckbox` test helper
   (which clicks the hidden input directly via `page.evaluate`).
